# Invoice Desk — AI-powered invoice extraction

A local full-stack invoice application with a React frontend and Python API. It reuses the existing DocTR OCR, selectable Gemini/Groq extraction, SQLite persistence, folder repository, deterministic validation, and review-history code. The app uses a single-pass baseline: self-consistency sampling and automatic retries are disabled, and reliability signals do not drive a multi-signal router. The OCR/grounding diagnostics remain available in the review UI; users can explicitly retry a document.

## Features
- React + Vite + TypeScript interface: dashboard, document library, folder tree, review queue, settings.
- Upload PDF, PNG, or JPEG; DocTR OCR; structured extraction through the configured Gemini or Groq provider.
- PDF preview alongside editable extracted fields, available evidence, OCR confidence, validation notes, and Approve / Retry / Reject actions.
- Larger, more readable frontend controls and a prominent dashboard upload action.
- Date parsing supports compact month-name OCR formats such as `SEP30/20`; order worksheets and similar document types receive a conservative manual-review warning.
- Persistent SQLite database and local file storage under `app_data/`.
- Folder/subfolder creation and document assignment.
- CSV export of approved invoices from a folder.
- Optional direct Google Sheets export using a service account.

## Requirements
- Windows 10/11
- Python 3.11 recommended (3.10–3.12 supported by the original pipeline)
- Node.js 20 or later
- Internet access for installing packages, downloading OCR model weights on first run, and API calls
- LLM API key for actual extraction

## Setup on Windows PowerShell

From the extracted `PBL_LY` directory:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
Copy-Item .env.example .env
notepad .env
```

Set `LLM_PROVIDER=gemini` and `GEMINI_API_KEY=...` in `.env` (copy `.env.example` first). Gemini 2.5 Flash is the default model. To use the previous provider instead, set `LLM_PROVIDER=groq` and `GROQ_API_KEY=...`. Do not share or commit `.env`. The first DocTR run downloads its model weights.

Install frontend dependencies once:

```powershell
cd frontend
npm install
cd ..
```

## Run the application

Open **two terminals** in the `PBL_LY` folder.

Terminal 1 — API:

```powershell
.\.venv\Scripts\Activate.ps1
python -m uvicorn api:app --host 127.0.0.1 --port 8000
```

Terminal 2 — frontend:

```powershell
cd frontend
npm run dev
```

Open http://127.0.0.1:5173. API health/docs: http://127.0.0.1:8000/api/health and http://127.0.0.1:8000/docs.

You can also use `run_backend.bat` and `run_frontend.bat` after setup.

## Google Sheets export (optional)

CSV export works without Google credentials and can be opened in Google Sheets. To enable direct export:

1. Enable the Google Sheets API in a Google Cloud project.
2. Create a service account and download its JSON key.
3. Create or choose a Google spreadsheet and share it with the service account's `client_email` as an editor.
4. Add these values to `.env`:
   - `GOOGLE_SERVICE_ACCOUNT_JSON=` path to the service-account JSON file, **or** the JSON contents as one line.
   - `GOOGLE_SHEETS_SPREADSHEET_ID=` spreadsheet ID from its URL.
5. Restart the API. Open a folder and select **Export to Sheets**.

The exporter uses `document_id` to update already-exported rows and append new approved invoices, so repeating an export does not intentionally duplicate records. Use a new blank sheet or keep the exact header row generated by the app.

## Tests

```powershell
python -m pytest -q
```

The original Streamlit smoke tests belong to the legacy interface and require Streamlit; they are retained in the repository as reference tests. The React frontend is source code and must be built with `npm run build` to verify TypeScript and Vite output.

## Data and security notes
- Uploaded documents and SQLite data are stored locally in `app_data/` by default.
- Never commit `.env`, service-account JSON keys, uploaded invoices, or the database.
- OCR confidence is a diagnostic signal, not a guarantee of extraction correctness.
- Review extracted totals against the original invoice before approval.
